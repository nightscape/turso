# CREATE MATERIALIZED VIEW

<Info>
**Turso Extension**: Materialized views are a Turso-specific feature not available in SQLite. This feature is experimental and must be [enabled before use](/docs/sql-reference/experimental-features).
</Info>

A materialized view stores precomputed query results on disk and automatically keeps them up to date using Incremental View Maintenance (IVM). Unlike standard views, reading from a materialized view does not re-execute the underlying SELECT.

## Syntax

```sql
CREATE MATERIALIZED VIEW [IF NOT EXISTS] view-name AS select-statement;
```

### Parameters

| Parameter | Description |
|-----------|-------------|
| `IF NOT EXISTS` | Prevents an error if a materialized view with the same name already exists. The statement is a no-op when the view is present. |
| `view-name` | A unique name for the materialized view within the database. |
| `select-statement` | The SELECT query that defines the materialized view's contents. |

## How Incremental View Maintenance Works

When you modify data in a table that underlies a materialized view, Turso incrementally updates the materialized view within the same transaction. There is no manual `REFRESH` step. The materialized view is always consistent with the base tables.

- Changes to the materialized view are committed or rolled back together with the changes to the base tables.
- Aggregations like `COUNT`, `SUM`, and `AVG` are maintained efficiently — Turso does not recompute the entire result set on each change.

## Current Limitations

- Supported aggregate functions are `COUNT`, `SUM`, `TOTAL`, `AVG`, `MIN`, and `MAX`, including `DISTINCT` arguments and `FILTER (WHERE ...)`. Other aggregate functions are not yet supported.
- `FULL OUTER JOIN`, window functions, and `ORDER BY`, `LIMIT`, or `OFFSET` in the defining query are not yet supported.
- Scalar and correlated subqueries are not yet supported. FROM-clause derived tables and CTEs are supported. For recursive CTEs, see [Recursive CTEs](#recursive-ctes).
- Virtual-table sources, virtual generated columns, non-deterministic expressions, bound parameters, and custom collations on grouping or deduplication keys are not yet supported.
- Materialized views on attached databases and materialized views under experimental MVCC mode are not yet supported.
- The `TEMPORARY` modifier is not supported for materialized views.

A materialized view may reference another materialized view. Turso maintains
the dependency chain in transaction order and prevents an upstream object from
being dropped while a dependent materialized view exists.

## Recursive CTEs

A materialized view can use `WITH RECURSIVE` with `UNION ALL`. Turso maintains it incrementally, like any other materialized view.

The recursive part of the CTE can join base tables with `JOIN` and `LEFT JOIN`, and can filter its base-table rows with `EXISTS` and `NOT EXISTS`. For `LEFT JOIN`, the recursive CTE must be on the left side. A subquery cannot read the recursive CTE or its columns.

These recursive CTE forms are not yet supported:

- `UNION` (without `ALL`) between the initial part and the recursive part.
- `ORDER BY`, `LIMIT`, or `OFFSET` in the recursive CTE.
- Aggregates, `DISTINCT`, `UNION`, `INTERSECT`, or `EXCEPT` in the recursive part.
- A recursive CTE inside another recursive CTE.
- The recursive CTE on the right side of a `LEFT JOIN`, or a subquery that reads the recursive CTE or its columns.

If the recursion does not end after 10000 rounds, for example because the data contains a cycle that no condition stops, the statement fails with `materialized view <name>: recursive CTE did not converge after 10000 rounds`. This applies to `CREATE MATERIALIZED VIEW` and to writes to the tables that the view reads.

```sql
CREATE TABLE node (id INTEGER PRIMARY KEY, parent INTEGER);

CREATE MATERIALIZED VIEW subtree AS
  WITH RECURSIVE t(id, depth) AS (
    SELECT id, 0 FROM node WHERE parent IS NULL
    UNION ALL
    SELECT n.id, t.depth + 1 FROM node n JOIN t ON n.parent = t.id
  ) SELECT id, depth FROM t;
```

## Examples

### Precomputed Aggregations

```sql
CREATE TABLE orders (
    id INTEGER PRIMARY KEY,
    customer_id INTEGER,
    amount REAL,
    created_at TEXT
);

-- Precompute per-customer totals
CREATE MATERIALIZED VIEW customer_totals AS
SELECT
    customer_id,
    COUNT(*) AS order_count,
    SUM(amount) AS total_spent
FROM orders
GROUP BY customer_id;

-- Fast read — no aggregation at query time
SELECT * FROM customer_totals WHERE total_spent > 1000;
```

### Automatic Updates

```sql
-- When new orders are inserted, customer_totals updates automatically
INSERT INTO orders VALUES (1, 100, 59.99, '2025-01-15');
INSERT INTO orders VALUES (2, 100, 24.50, '2025-01-16');

-- Reflects both inserts without a manual refresh
SELECT * FROM customer_totals WHERE customer_id = 100;
-- customer_id: 100, order_count: 2, total_spent: 84.49
```

### Filtered Summary

```sql
CREATE MATERIALIZED VIEW recent_activity AS
SELECT
    customer_id,
    COUNT(*) AS recent_orders
FROM orders
WHERE created_at >= '2025-01-01'
GROUP BY customer_id;
```
